# TorrentFlow 0.2.0 — CPU и память

Контрольный прогон: после проверки окна до начала тайминга AX-чтение, снимки и взаимодействия с окном не выполнялись.

Измерен настоящий Release-процесс GUI TorrentFlow, а не отдельный тест движка. macOS 27.0.1, arm64; Apple M4. CPU 100% соответствует одному ядру.

## Методика

- Сэмплы каждые 0,5 с через macOS `proc_pidinfo(PROC_PIDTASKINFO)`: суммарное процессорное время user + system переводится из Mach ticks в наносекунды через `mach_timebase_info`; резидентная память RSS. `proc_pid_rusage` даёт отдельный physical footprint.
- До начала измерения приложение проходит штатный запуск, минимум 2 секунды прогрева и подтверждение видимости окна. В каждой фазе учитывается только PID приложения; локальный сид и скрипт измерения — отдельные процессы.
- Передача: 256 МиБ, локальный TCP-пир, ограничение класса локальных пиров сида 8 МиБ/с, настоящий magnet с получением метаданных и подтверждением выбора. Во время активной загрузки открыт нижний инспектор пиров. После завершения задача приостановлена, открыты логи.
- DHT/LSD/UPnP в изолированном тесте выключены. У копии приложения отдельный Bundle ID `com.zel0th.TorrentFlow.Performance`, код и данные Mach-O и ресурсы совпадают с Release. Переподпись меняет встроенную подпись, поэтому полные SHA-256 Release и QA различаются; оба хеша и общий хеш содержимого Mach-O сохранены в JSON. Проверка нормализует только встроенную подпись, её служебные поля и размеры `__LINKEDIT`. Рабочая конфигурация и папки пользователя не менялись. Тестовые данные находятся в собственном временном каталоге.
- Загруженный файл проверен SHA-256: `bb587de23a7837f7bfb939ddb50cbb030ed9522239309943c389445b79f553c3`.
- Полный набор сэмплов и сведения о бинарном файле: `Performance-0.2.0.json`.

## Границы результата

Это один локальный замер на данном Mac: один торрент и один пир, без интернет-трекеров и VPN. Он проверяет стоимость интерфейса, обмена данными и инспектора, но не заменяет долговременный нагрузочный тест на сотнях задач и тысячах пиров. RSS включает отображённые страницы файлов; physical footprint и RSS имеют разные определения. Пиковый CPU — максимум интервала 0,5 с, а не мгновенное значение.

## Повторная проверка пика

Предыдущий прогон с AX-чтением и снимками окна сохранён в [Performance-0.2.0-UI-observation.md](Performance-0.2.0-UI-observation.md) и соответствующем JSON. В нём CPU вкладки логов достиг 97.55% на интервале 0,5 с; в отдельном контрольном прогоне без наблюдения — 21.10%. Это два измерения одного исполняемого файла; конкретная причина пика не установлена.
